# Запись на сайте

Одностраничный сайт с формой записи. Клиент выбирает день и время, оставляет
имя и контакт, заявка приходит владельцу в Telegram.

```
docs/index.html              страница и форма (её отдаёт GitHub Pages)
netlify/functions/book.mjs   бэкенд №1, Netlify Function
src/worker.js                бэкенд №2, Cloudflare Worker
netlify.toml                 конфиг Netlify
wrangler.toml                конфиг Cloudflare
```

## Как это работает

1. Клиент выбирает день и время, пишет имя и контакт.
2. Страница шлёт `POST` с заявкой на бэкенд.
3. Бэкенд проверяет данные, режет спам и отправляет сообщение в Telegram.
4. Бот присылает владельцу: имя, контакт, дату, время, комментарий.

Бэкендов два, и они независимы. Из некоторых сетей зарубежные хостинги
отвечают через раз, поэтому страница перебирает адреса по очереди, пока один
не ответит. Тот адрес, который сработал, запоминается в браузере и
используется первым в следующий раз.

Токен бота лежит в переменных Netlify и в секретах Cloudflare, в браузер он
не попадает.

## Переменные

На обоих бэкендах нужны `BOT_TOKEN` и `CHAT_ID`. `CHAT_ID` может быть списком
получателей через запятую.

```powershell
# Cloudflare
npx wrangler secret put BOT_TOKEN
npx wrangler secret put CHAT_ID

# Netlify
npx netlify env:set BOT_TOKEN "ваш_токен"
npx netlify env:set CHAT_ID "ваш_id"
```

Локально переменные лежат в `.env` и `.dev.vars`, оба файла в git не попадают.

## Выложить изменения

```powershell
git add -A
git commit -m "что поменяли"
git push                 # страница на GitHub Pages

npx wrangler deploy      # бэкенд Cloudflare
npx netlify deploy --prod --dir=docs --functions=netlify/functions
```

GitHub Pages обновляется сам через минуту после `git push`.

## Что можно поправить под себя

В `docs/index.html`, блок `CONFIG` в начале скрипта:

```js
daysAhead: 14,        // на сколько дней вперёд показывать слоты
slotMinutes: 30,      // длина слота
workStart: 10 * 60,   // начало дня, в минутах от полуночи
workEnd: 19 * 60,     // конец дня
closedWeekdays: [0],  // 0 = воскресенье, 6 = суббота
minLeadMinutes: 120   // нельзя записаться меньше чем за 2 часа
```

Там же `endpoints` — список бэкендов. Если добавите третий, впишите его
в массив и в `connect-src` метатега CSP выше по файлу.

## Ограничения

- Занятость не проверяется. Двое могут выбрать одно время, решает владелец
  при подтверждении.
- Лимит частоты (5 заявок за 10 минут с одного IP) хранится в памяти
  бэкенда. DDoS он не остановит, но спам-скрипты отсекает.
- Заявки нигде не сохраняются, кроме чата Telegram.
- Если сеть клиента совсем не пускает ни один из бэкендов, форма покажет
  ошибку. Такое бывает на мобильных операторах с жёсткой фильтрацией.
