# Запись на сайте

Одностраничный сайт с формой записи. Клиент выбирает день и время, оставляет
имя и контакт, заявка приходит владельцу в Telegram. Своего сервера нет:
страница статическая, заявку принимает Netlify Function.

```
public/index.html            страница и форма
netlify/functions/book.mjs   приём заявки + отправка в Telegram
netlify.toml                 конфиг Netlify
src/worker.js                тот же бэкенд для Cloudflare, запасной вариант
wrangler.toml                конфиг Cloudflare
```

## Как это работает

1. Клиент выбирает день и время, пишет имя и контакт.
2. Страница шлёт `POST /api/book` на тот же домен.
3. Функция проверяет данные, режет спам и отправляет сообщение в Telegram.
4. Бот присылает владельцу: имя, контакт, дату, время, комментарий.

Токен бота лежит в переменных Netlify и в браузер не попадает.

## Первый запуск

```powershell
cd C:\Users\user_zxc\zapis
npm install
npx netlify login
```

### 1. Создать бота

1. В Telegram открыть `@BotFather`.
2. Отправить `/newbot`, придумать имя и username.
3. Скопировать токен вида `123456789:AA...`.

Важно: если токен уже кому-то отправляли, в `@BotFather` сделайте `/revoke`,
старый перестанет работать, и возьмите новый.

### 2. Узнать chat_id

1. Открыть своего бота и нажать `/start`. Без этого бот не сможет вам писать.
2. Написать боту любое сообщение.
3. Открыть в браузере:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
4. Найти `"chat":{"id":123456789}`. Это и есть `CHAT_ID`.

Второй способ: написать `@userinfobot`, он покажет ваш id.

### 3. Прописать переменные

На продакшене:

```powershell
npx netlify env:set BOT_TOKEN "ваш_токен"
npx netlify env:set CHAT_ID "ваш_id"
```

После этого нужен повторный деплой, функция читает переменные при запуске.

Локально переменные лежат в `.env` в корне проекта:

```
BOT_TOKEN=ваш_токен
CHAT_ID=ваш_id
```

### 4. Проверить локально

```powershell
npm run dev
```

Открыть `http://localhost:8888`, выбрать время, отправить заявку. Сообщение
должно прийти в Telegram. Отправка настоящая, из вашей сети, поэтому если
Telegram не открывается без VPN, локальная проверка не сработает.

### 5. Выложить

```powershell
npm run deploy
```

CLI покажет адрес вида `https://zapis-xxxx.netlify.app`. Это и есть готовый
сайт. Свой домен можно прикрутить позже в панели Netlify.

## Что можно поправить под себя

В `public/index.html`, блок `CONFIG` в начале скрипта:

```js
daysAhead: 14,        // на сколько дней вперёд показывать слоты
slotMinutes: 30,      // длина слота
workStart: 10 * 60,   // начало дня, в минутах от полуночи
workEnd: 19 * 60,     // конец дня
closedWeekdays: [0],  // 0 = воскресенье, 6 = суббота
minLeadMinutes: 120   // нельзя записаться меньше чем за 2 часа
```

Тексты на странице меняются прямо в `public/index.html`.

## Ограничения

- Занятость не проверяется. Двое могут выбрать одно время, решает владелец
  при подтверждении. Для настоящей сетки занятости нужно хранилище,
  например Netlify Blobs: функция записывает занятые слоты и отдаёт их странице.
- Лимит частоты (5 заявок за 10 минут с одного IP) хранится в памяти функции.
  DDoS он не остановит, но спам-скрипты отсекает.
- Заявки нигде не сохраняются, кроме чата Telegram. История есть в чате.
- `CHAT_ID` может быть списком получателей через запятую.

## Запасной вариант на Cloudflare

Файлы `src/worker.js` и `wrangler.toml` рабочие и проверены. Если Netlify
не подойдёт, сайт поднимается командами `npx wrangler secret put BOT_TOKEN`,
`npx wrangler secret put CHAT_ID` и `npx wrangler deploy`. Из этой сети
Cloudflare отвечает через раз, поэтому основным выбран Netlify.
